# 표준 QA 테스트 케이스 Markdown 테이블 형식 정의

이 문서는 QA 테스트 케이스의 표준 형식을 정의합니다. 모든 테스트 케이스 생성, 수정, 실행 결과 보고는 반드시 아래에 정의된 Markdown 테이블 형식을 따라야 합니다.

## 테이블 구조

| ID | 기능 분류 | 테스트 항목 | 실행 절차 | 예상 결과 | 결과 (Pass/Fail/Blocked) | 비고 (실패 시 상세 내용) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| | | | | | | |

---

## 각 열(Column) 설명

1.  **ID**:
    *   각 테스트 케이스의 고유 식별자입니다.
    *   `[TC-XXX]` 형식으로 작성합니다. (예: `[TC-001]`)

2.  **기능 분류**:
    *   테스트 케이스가 속한 큰 기능의 이름이나 분류입니다.
    *   예: `사용자 인증`, `게시물 관리`, `결제 시스템`
    *   동일한 기능 분류에 속한 테스트 케이스는 이 열에 같은 값을 가집니다.

3.  **테스트 항목**:
    *   해당 테스트 케이스가 검증하고자 하는 목표를 요약하여 작성합니다.
    *   예: `유효한 정보로 회원가입`, `존재하지 않는 게시물 조회`

4.  **실행 절차**:
    *   테스트를 재현하기 위한 구체적이고 순서가 명확한 절차입니다.
    *   단계별로 번호(1., 2., 3.)를 매기거나, `<br>` 태그를 사용해 줄을 바꿔 명확하게 구분합니다.
    *   예: `1. /login 접속<br>2. ID: 'test', PW: '123' 입력<br>3. '로그인' 버튼 클릭`

5.  **예상 결과**:
    *   `실행 절차`를 따랐을 때 나와야 하는 정상적인 결과입니다.
    *   구체적으로 작성합니다.
    *   예: `메인 페이지로 이동하며 'test님 환영합니다' 메시지 표시`

6.  **결과 (Pass/Fail/Blocked)**:
    *   테스트 케이스 생성 시에는 이 칸을 **반드시 비워두어야 합니다.**
    *   테스트 실행(`QA.run`) 후에 채워지는 칸입니다.
    *   다음 세 가지 값 중 하나만 가질 수 있습니다:
        *   `Pass`: 예상 결과와 실제 결과가 일치함.
        *   `Fail`: 예상 결과와 실제 결과가 다름.
        *   `Blocked`: 선행 조건 미충족, 테스트 환경의 문제 등으로 테스트를 진행할 수 없음.

7.  **비고 (실패 시 상세 내용)**:
    *   테스트 케이스 생성 시에는 이 칸을 **반드시 비워두어야 합니다.**
    *   `결과`가 `Fail` 또는 `Blocked`일 경우, 그 원인과 실제 결과를 상세히 기록하는 칸입니다.
    *   실패 로그, 에러 메시지, 스크린샷 파일 경로 등을 포함할 수 있습니다.
    *   예: `Actual: '서버 내부 오류' 팝업 발생. (screenshot: /reports/screenshots/TC-005_fail.png)`
